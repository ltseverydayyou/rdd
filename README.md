# RDD (Roblox Deployment Downloader)

This repository is an independently maintained fork of [Latte Softworks' RDD](https://github.com/latte-soft/rdd), licensed under the MIT License.

RDD locally assembles Roblox Player and Studio deployments in the browser using deployment files served directly from Roblox's CDN. Deployment binaries are not proxied through this repository.

## Improvements in this fork

- Automatic latest-version resolution with a locally cached version index.
- Previous, future, observed-history, and custom version modes.
- Rolling version history generated by GitHub Actions.
- Windows Player and Studio support.
- macOS Player/Studio presets for Intel and ARM64 deployment paths.
- Real package download and final ZIP progress.
- Bounded parallel package workers to reduce network/RAM spikes.
- Cancel and retry controls.
- Automatic package retry on transient network failures.
- Package manifest inspector with compressed/extracted size totals.
- Full, core, minimal, content-only, and custom package selections.
- MD5 and compressed-size verification for downloaded packages.
- Unknown package detection with safe preservation at the output root.
- Saved local presets and recent-download history.
- Shareable permanent links that preserve downloader options.
- Installable PWA shell for the RDD interface.

## Usage

Open the hosted page and choose a binary, channel, version mode, package set, and download options. For most users, leaving the version mode on **Latest** is sufficient.

Direct links are also supported:

```text
?channel=LIVE&binaryType=WindowsPlayer&versionMode=latest
?channel=LIVE&binaryType=WindowsPlayer&versionMode=previous
?channel=LIVE&binaryType=WindowsPlayer&versionMode=custom&version=version-xxxxxxxxxxxxxxxx
```

Supported binary types:

```text
WindowsPlayer
WindowsStudio64
MacPlayer
MacStudio
MacPlayerArm64
MacStudioArm64
```

You can still use `blobDir` to override the deployment path manually when needed.

## Version cache

`.github/workflows/update-rdd-versions.yml` refreshes `api/versions/` on a schedule. Current versions prefer Roblox's ClientSettings endpoint; WEAO version data is used for previous/future tracking and as a fallback. The workflow also maintains a rolling local history so observed versions remain selectable later.

## Architecture

Windows deployments are assembled from `rbxPkgManifest.txt` packages using JSZip. RDD parses the manifest metadata, limits concurrent package work, verifies each downloaded package, extracts known package roots, preserves unknown packages, and produces the final ZIP locally in the browser.

Mac deployments use Roblox's direct deployment ZIP archives.
